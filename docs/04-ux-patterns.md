# รูปแบบ UX

เอกสารนี้แยกรูปแบบที่ใช้ในแอปเป็นข้อ ๆ ทุกข้อเขียนในรูป "ปัญหา, วิธีที่แอปทำ, ยกไปใช้อย่างไร" เพื่อเอาไปใช้กับแอปใหม่ได้แม้โดเมนต่างกัน

## 1. ใช้ได้โดยไม่ต้องล็อกอิน แต่มีแอดมินแยก

ผู้เล่นส่วนใหญ่แค่อยากดูและช่วยจด การบังคับล็อกอินจะทำให้คนช่วยน้อยลง

แอปจึงให้ทุกคนอ่านและเขียนทีละจุดได้เลย ส่วนงานที่ทำลายข้อมูลได้มาก (ล้างทั้งด่าน, เขียนทับทั้งแถว, เปลี่ยนด่านหลังมีข้อมูลแล้ว) อยู่หลังรหัสแอดมิน และปุ่ม Admin Login ซ่อนอยู่ล่างสุดของแท็บตั้งค่า ไม่อยู่ในสายตาผู้ใช้ทั่วไป

ยกไปใช้: แยกงานเป็นสองระดับ งานเล็กที่ย้อนได้ให้ทุกคนทำ งานใหญ่ให้แอดมิน และให้ server ตรวจเงื่อนไขทุกครั้ง (ด่านตรงกัน, ยังไม่ล็อก) ไม่พึ่ง UI อย่างเดียว

## 2. รอบเวลาที่ server เป็นคนตัดสิน

ข้อมูลต้องหมดอายุทุกสัปดาห์ตามเวลาของเกม ไม่ใช่เวลาเครื่องผู้ใช้

server คำนวณกุญแจรอบ (วันที่ของวันจันทร์ 22:00 รอบล่าสุด เวลาไทย) ทุก request แล้วเทียบกับวันที่ในชีท ไม่ตรง = สัปดาห์ใหม่ ฝั่ง client ได้ flag `isNewWeek`, `isMapSet`, `canChangeMap` ไปใช้ตัดสินใจ UI เลย ไม่ต้องคำนวณเวลาเอง

client จำค่ารายสัปดาห์ด้วยกุญแจเดียวกัน เช่น `got_team_week = mapDate` ถามทีมสัปดาห์ละครั้ง

ยกไปใช้: ข้อมูลที่มีรอบ (รายวัน รายสัปดาห์ รายซีซัน) ให้มี "กุญแจรอบ" ที่ server สร้าง แล้วใช้กุญแจนั้นทั้งตอนเก็บและตอนจำสถานะในเครื่อง ไม่ต้องมี cron ล้างข้อมูล

## 3. ขั้นแรกที่เปิดเองและดักทุกทางเข้า

ถ้ายังไม่เลือกด่านของสัปดาห์ ข้อมูลทุกอย่างไม่มีความหมาย

แอปเปิดหน้าต่างเลือกด่านทันทีที่โหลด (`openMapPicker(true)`) พร้อมแถบแจ้งเตือนสีเหลือง "New Week Reset!" ที่หายเองใน 5 วินาที ผู้ใช้ปิดหน้าต่างเพื่อดูแอปก่อนได้ (ปุ่ม X และแตะพื้นหลัง) แต่ทุกทางที่จะบันทึกข้อมูล (ดินสอ, แตะทีม) จะเด้งกลับมาหน้าต่างนี้ถ้ายังไม่มีด่าน ระหว่างนั้นถ้ามีคนอื่นเลือกด่านแล้ว การ refresh ครั้งถัดไปจะปิดหน้าต่างให้เอง

คอมเมนต์ในโค้ดเขียนว่า force = ปิดไม่ได้จนกว่าจะเลือก แต่ `openMapPicker` แสดงปุ่ม X ทุกครั้ง พฤติกรรมจริงจึงเป็นแบบที่อธิบายข้างบน ถ้าแอปใหม่ต้องการบังคับจริง ให้ซ่อนปุ่ม X และเอาออกจาก listener ปิดเมื่อแตะพื้นหลังเมื่อ `force` เป็น true

ข้อความในหน้าต่างเปลี่ยนตามสถานการณ์: "Select This Week's Map" เมื่อบังคับ, "Change This Week's Map" เมื่อเปิดเองเพื่อเปลี่ยน และมีบรรทัดเล็กใต้รายการบอกเงื่อนไขล็อก "แก้ไขด่านได้จนกว่าจะมีการบันทึก Wave แรก"

ยกไปใช้: งานตั้งต้นที่ต้องมีก่อนงานอื่น ให้เป็น modal ที่เปิดเอง และทุกปุ่มที่ต้องพึ่งมันพากลับมาที่ modal นี้แทนการแสดง error

## 4. ลำดับ modal ตอนเปิดแอป

หลาย modal อยากแสดงตอนเปิดแอป (เลือกด่าน, What's New, ถามทีม) ถ้าเด้งพร้อมกันผู้ใช้จะสับสน

แอปเรียงลำดับไว้: เลือกด่าน → What's New → ถามทีม ปิดอันหนึ่งแล้วค่อยเรียกอันถัดไป (`closeFeatureModal` เรียก `maybeAskTeam`) และ `maybeAskTeam` ตรวจก่อนว่ามี modal อื่นเปิดอยู่ไหม ถ้ามีก็ไม่เปิด แล้วรอโอกาสถัดไป (เช่นหลัง refresh)

ยกไปใช้: เขียนฟังก์ชัน `maybeShowX()` ที่ตรวจทั้งเงื่อนไขของตัวเองและ "มี modal อื่นเปิดอยู่ไหม" แล้วเรียกซ้ำได้ทุกจุดที่สถานะเปลี่ยน

## 5. บันทึกร่วมกันทีละจุด (per-field autosave)

หลายคนจดเวฟเดียวกันพร้อมกัน ถ้าบันทึกทั้งเวฟ คนที่กดทีหลังจะลบของคนแรก

แอปทำแบบนี้:

1. ทุกครั้งที่แตะ ค่าใหม่เข้าคิวของจุดนั้น (`queuePoint`) และตั้งเวลา 1.5 วินาทีใหม่ แตะต่อเนื่องจะส่งแค่ค่าสุดท้าย
2. ครบเวลา ถ้าค่าเท่ากับที่บันทึกล่าสุด ไม่ส่ง
3. ส่งเฉพาะจุดนั้น server ล็อก อ่านเซลล์ แก้ตำแหน่งเดียว เขียนกลับ
4. server คืนข้อมูลล่าสุดทั้งหมด client แทน state แล้ว render ทั้งหน้า ผู้ใช้เห็นของคนอื่นด้วยทันที
5. แต่ละคิวมี `ver` นับครั้งที่แก้ ถ้าผลกลับมาแต่ผู้ใช้แก้จุดนั้นต่อไปแล้ว สถานะจะไม่ถูกเปลี่ยนเป็น "บันทึกแล้ว" ผิด ๆ
6. ปิด sheet ก่อนครบเวลา: ส่งคิวที่ค้างทันที
7. ตอนโหลดข้อมูลล่าสุดมาใส่ sheet จุดที่ยังรอส่ง (`wait`, `saving`, `error`) ใช้ค่าในเครื่อง ไม่ถูกทับด้วยค่าจาก server

แต่ละจุดแสดงสถานะเล็ก ๆ ที่มุมขวาของหัวจุด

| สถานะ | ไอคอน | ข้อความ TH / EN |
|---|---|---|
| `wait` | `fa-clock` เทา | รอบันทึก / Pending |
| `saving` | `fa-circle-notch fa-spin` indigo | กำลังบันทึก / Saving |
| `saved` | `fa-circle-check` emerald | บันทึกแล้ว / Saved |
| `error` | `fa-triangle-exclamation` rose (เป็นปุ่ม) | ไม่สำเร็จ แตะเพื่อลองใหม่ / Failed, tap to retry |

ถ้า error เกิดตอน sheet ปิดไปแล้ว แสดง toast สีแดงแทน เปิด sheet ครั้งใหม่ สถานะ "บันทึกแล้ว" ของรอบก่อนถูกล้าง แต่จุดที่ยังค้างหรือ error ยังอยู่

ปุ่มล่างของ sheet สำหรับผู้เล่นเป็น "Done (เสร็จ)" ไม่ใช่ "Save" เพราะบันทึกไปแล้ว คำอธิบายใต้หัว sheet บอกว่า "เลือกแล้วบันทึกให้ทุกคนอัตโนมัติใน 1.5 วินาที"

ยกไปใช้: ฟอร์มที่หลายคนแก้พร้อมกัน ให้บันทึกระดับ field พร้อม debounce, ตรวจค่าซ้ำก่อนส่ง, server merge ระดับ field ใต้ lock, ตอบกลับด้วย snapshot ล่าสุด และแสดงสถานะต่อ field โครง `ptState` ใช้ซ้ำได้กับข้อมูลหลายชนิด (แอปนี้ใช้กับทั้งจุดเกิดและทีมผ่าน `PT_KIND`)

## 6. ข้อมูลเปลี่ยนใต้เท้า: ทิ้งแล้วโหลดใหม่

ระหว่างผู้ใช้กำลังจด อาจมีคนเปลี่ยนด่านหรือขึ้นสัปดาห์ใหม่

ทุก request เขียนส่งชื่อด่านไปด้วย server เทียบกับชีท ถ้าไม่ตรงตอบ `map_mismatch` หรือ `no_map` client ทิ้งคิวทั้งหมด ปิด sheet โหลดใหม่ แล้วบอกผู้ใช้ว่าเกิดอะไร (หรือเปิดหน้าต่างเลือกด่าน)

ยกไปใช้: request เขียนทุกตัวแนบ "บริบท" ที่ client เชื่อว่าเป็นอยู่ (เวอร์ชัน, id พ่อแม่) ให้ server ปฏิเสธด้วย code ที่ชัดเจน และ client มีทางเดียวสำหรับ code นั้นคือ reset แล้วโหลดใหม่

## 7. refresh เมื่อกลับเข้าแอป

ผู้เล่นสลับไปเล่นเกมแล้วกลับมา ข้อมูลในจออาจเก่า

`visibilitychange` เป็น `visible` → เรียก `getLatestSpawnData` (เบา ไม่นับผู้เข้าชม) ยกเว้นตอนเป็นแอดมินหรือ sheet แก้ไขเปิดอยู่ (ไม่อยากให้ข้อมูลกระตุกระหว่างจด)

ยกไปใช้: แทน polling ใช้ `visibilitychange` และ refresh หลังเขียนทุกครั้ง มี endpoint อ่านแบบเบาแยกจาก endpoint โหลดครั้งแรก

## 8. ใช้งานระหว่างเล่น: แตะเดียว ได้ทั้งเวลาและเสียง

ระหว่างเล่นผู้ใช้มองจอได้แวบเดียว

- แตะแถวเวฟย่อย = เริ่มนับถอยหลัง + อ่านออกเสียง + ไฮไลต์แถว (พื้น indigo, ring, ขยาย 1.02 เท่า) + เวฟอื่นจาง 40%
- เลขเวฟย่อยกลายเป็นนาฬิกา `1:30` ในตำแหน่งเดิม ไม่มี element ใหม่
- หมดเวลา ขยับไปเวฟย่อยถัดไปเอง อ่านเสียงต่อ ผู้ใช้ไม่ต้องแตะซ้ำ
- แตะแถวเดิมอีกครั้ง = หยุด
- timer อัปเดตเฉพาะ text ของ element ที่มี id (`active-timer-el`, `map-timer-el`, `text-timer-el`) ไม่ render ทั้งหน้าทุกวินาที
- ในแท็บแผนที่ เลือกเวฟย่อยจากตาราง = เริ่มเวลาเหมือนกัน แต่แตะซ้ำไม่หยุด (กันกดพลาด)

เสียง:

- ภาษาไทย: `เวฟที่ 1 จุด 2: โรงซ้าย, หอขวา สีส้ม` ใช้ชื่อย่อติดกับฝั่ง (ตัดขีดออก) สีพูดทีละสี
- อังกฤษ: `Wave 1.2: Foundry Left, Keep Right orange`
- เลือกทีมแล้ว อ่านเฉพาะจุดของทีมตัวเอง
- เปลี่ยนการตั้งค่าเสียงแล้วพูดยืนยันทันที ("เปิดระบบเสียง", "ภาษาไทย", "ความเร็ว 1.5 เท่า") เพื่อให้รู้ว่าเสียงทำงาน
- `speechSynthesis.cancel()` ก่อนพูดทุกครั้ง ไม่ให้เสียงซ้อน
- ความเร็ว 1.0 ถึง 2.5 ปรับด้วย slider หรือแตะ badge วนค่าทีละ 0.25

ยกไปใช้: แอปที่ใช้ระหว่างทำอย่างอื่น ให้ action หลักเป็นแตะเดียวที่ให้ feedback หลายช่องทาง (ภาพ เวลา เสียง) และเดินต่อเองได้

## 9. ตัวกรองส่วนตัวที่ไม่ซ่อนข้อมูล

ทีม A กับ B ต้องเห็นข้อมูลชุดเดียวกัน แต่สนใจคนละจุด

การแบ่งทีมเป็นข้อมูลแชร์ (ทุกคนเห็นเหมือนกัน) ส่วน "ทีมของฉัน" เป็นค่าในเครื่อง เลือกแล้วจุดของอีกทีมจางลง (opacity 25%) ไม่หายไป และป้ายฝั่งเปลี่ยนเป็นสีทีม (A = sky, B = fuchsia) แถบเลือกทีมตรึงใต้แท็บ สลับได้ในแตะเดียว และมี "ทั้งหมด"

ถามทีมอัตโนมัติเมื่อสัปดาห์นี้มีคนแบ่งทีมแล้วและเครื่องนี้ยังไม่ได้ตอบ ถามสัปดาห์ละครั้ง มีตัวเลือก "ดูทั้งหมด (ไม่เลือกทีม)" ให้ออกได้

ทีมที่ยังไม่ได้กำหนดให้เดาว่าเป็นอีกทีม (กำหนด A จุดเดียว ที่เหลือกลายเป็น B) ผู้ใช้กดน้อยลง

ยกไปใช้: ตัวกรองมุมมองส่วนตัวให้ "ลดความเด่น" ดีกว่าซ่อน เพราะยังเห็นภาพรวม และให้ค่าตั้งต้นที่ฉลาดแทนการบังคับกรอกทุกช่อง

## 10. หลายมุมมองของข้อมูลชุดเดียว

ผู้ใช้แต่ละคนอ่านข้อมูลต่างกัน บางคนจำ emoji บางคนชอบตัวหนังสือ บางคนต้องเห็นตำแหน่งจริง

แท็บไอคอน ตัวหนังสือ และแผนที่ แสดงข้อมูลชุดเดียวกัน ใช้ภาษาภาพเดียวกัน (การ์ดต่อเวฟ, ลายน้ำ W1-W4, ปุ่มดินสอขวาสุด, ไฮไลต์เวฟที่เล่นอยู่) สลับแล้วไม่เสีย state (timer เดินต่อ) แท็บแผนที่ซ่อนเองถ้าโหลด `maps/*.js` ไม่ได้ และแอดมินเห็นแค่มุมมองไอคอนเสมอ

ยกไปใช้: มุมมองหลายแบบให้มาจาก state เดียวและฟังก์ชัน render แยกต่อมุมมอง ไม่เก็บ state ในมุมมอง

## 11. ชื่อสั้นสำหรับดู ชื่อเต็มสำหรับบันทึก

จอมือถือแคบ แต่ตอนบันทึกต้องไม่สับสน

- หน้าดูใช้ชื่อย่อ: `นา`, `โรง`, `Forge`, `Grave` และฝั่ง `-ซ้าย` / `-L`
- หน้าบันทึกใช้ชื่อเต็มทั้งสองภาษา (อังกฤษตัวใหญ่ ไทยตัวเล็กใต้)
- เสียงใช้ชื่อย่อติดกับฝั่ง
- แท็บตั้งค่ามีตารางคำย่อของด่านนี้ (emoji, คำย่อ, ชื่อเต็ม) และความหมายของ L/C/R
- ค่าที่เก็บในชีทเป็น id อังกฤษเสมอ เปลี่ยนชื่อแสดงผลได้ไม่กระทบข้อมูล
- ชื่อกับฝั่งแยก span `whitespace-nowrap` คั่นด้วย `<wbr>` จอแคบตัดบรรทัดตรงขีดเท่านั้น ไม่ตัดกลางคำ

ลำดับหาชื่อ: ตารางในโค้ด (`NAMES_TH`, `SHORT_EN`) → ชื่อจากชีท → id

## 12. สองภาษาในที่เดียว

ผู้เล่นมีทั้งไทยและต่างชาติ

แอปใช้สองวิธีปนกัน

- ข้อความระบบที่ไม่ค่อยเปลี่ยน (หัว modal, ปุ่ม, error) เขียนสองภาษาพร้อมกัน อังกฤษเป็นบรรทัดหลัก ไทยตัวเล็กในวงเล็บหรือบรรทัดล่าง เช่น `Confirm<br/><span class="text-[10px] font-normal">ยืนยัน</span>`
- ข้อความที่อยู่ในพื้นที่จำกัดหรือเป็นข้อมูล (ชื่อแท็บ, ชื่อจุด, แถบทีม, คำอธิบายแท็บทีม, หน้าต่างถามทีม) สลับตามภาษาที่เลือก ผ่าน `uiLang()` และ object `{ th, en }`
- What's New มีปุ่มสลับภาษาของตัวเอง เปิดมาตามภาษาของแอป

ยกไปใช้: ถ้าไม่อยากทำ i18n เต็มรูป ใช้กติกานี้ได้ ข้อความกำกับปุ่มสั้น ๆ ใส่สองภาษา ข้อความยาวหรือในที่แคบสลับตามภาษา เก็บข้อความใน object `{ th, en }` ข้างข้อมูล

## 13. ยืนยันก่อนทำลายข้อมูล, toast เมื่อสำเร็จ

| เหตุการณ์ | feedback |
|---|---|
| สำเร็จ | toast ด้านบน หายใน 3 วินาที ไอคอนเขียว |
| ผิดพลาดที่ผู้ใช้ต้องรู้ | modal ไอคอนแดง ปุ่ม OK |
| ผิดพลาดระหว่างทำงานเบื้องหลัง | toast ไอคอนแดง |
| ทำลายข้อมูล (Clear, Overwrite map, Exit ไม่ save) | modal เหลือง ปุ่ม Cancel + Confirm |
| กำลังส่ง | ปุ่มที่กดเปลี่ยนเป็น spinner และ disable จนเสร็จ แล้วคืนข้อความเดิม |

`showModal(type, title, desc, onConfirm)` ตัวเดียวใช้ได้ทั้ง error, warning, confirm

## 14. What's New ที่ดูแลง่าย

รายการฟีเจอร์อยู่ใน array เดียว (`FEATURES_V3`) แต่ละรายการมี icon, class สีของกล่อง, `th: [หัว, คำอธิบาย]`, `en: [...]` render ออกมาทั้งสองภาษาจาก array นี้ เปิดเองครั้งแรกต่อเครื่องด้วย key `got_feature_v3_seen` ขึ้นเวอร์ชันใหม่ก็เปลี่ยน key

## 15. ปิด modal ได้หลายทาง

- ปุ่ม X มุมขวาบน (วงกลม 32px)
- แตะพื้นหลังนอกกล่อง (มีทั้ง `onclick` บน backdrop และ listener รวมที่ `window`)
- ข้างในกล่องมี `event.stopPropagation()` กันแตะในกล่องแล้วปิด
- modal ที่ต้องตอบ (ถามทีม, What's New) ไม่ปิดเมื่อแตะพื้นหลัง

## 16. ปรับเพื่อมือถือ

- `user-scalable=no`, `maximum-scale=1.0` และ `* { touch-action: manipulation; }` กันแตะสองครั้งแล้วซูม (iOS ไม่สน `user-scalable=no`)
- `100dvh` และ `-webkit-fill-available` แก้ความสูงจอบน Safari
- `env(safe-area-inset-*)` ที่ด้านบนแอปและด้านล่างของแถบล่างและ sheet
- meta `apple-mobile-web-app-capable` ให้ add to home screen แล้วเต็มจอ
- ซ่อน scrollbar (`::-webkit-scrollbar { display: none; }`)
- ปุ่มสำคัญสูงอย่างน้อย 36px ปุ่มดินสอ 36 ถึง 40px
- sheet แก้ไขวางใต้แถบแท็บพอดี (คำนวณ `paddingTop` จากตำแหน่งแถบแท็บตอนเปิด) และเลื่อนกลับไปจุดที่ 1 ทุกครั้ง
- feedback การกด `active:scale-95` แทน hover

## 17. ป้องกันความผิดพลาดในตัว UI

- ปุ่มเลือกสถานที่ที่เลือกอยู่ แตะซ้ำ = ยกเลิก (ล้างฝั่งและสีด้วย)
- เปลี่ยนสถานที่ = ล้างฝั่งและสีเก่า เริ่มใหม่
- ส่วนเลือกฝั่งแสดงเฉพาะฝั่งที่สถานที่นั้นมีจริง (อ่านจาก `maps/*.js`)
- ส่วนเลือกสีแสดงเฉพาะด่านที่มีสีและเมื่อเลือกสถานที่แล้ว
- เวฟ 1-3 แตะสีใหม่ = แทนที่ เวฟ 4 = เพิ่มได้ถึงสอง บอกจำนวนสูงสุดข้างหัวข้อ
- ปุ่มเปลี่ยนด่านแสดงเฉพาะเมื่อยังเปลี่ยนได้
- dropdown เลือกด่านใช้ได้เฉพาะแอดมิน

## 18. รูปแบบจากต้นแบบแผนที่ (`maps/engine.js`)

ต้นแบบนี้ยังไม่ต่อ backend แต่มีรูปแบบที่ใช้ซ้ำได้

- bottom sheet ที่เลื่อนขึ้นจากล่าง (`translateY(100%)` → `none`, 240ms `cubic-bezier(.2,.8,.2,1)`) มีแถบจับด้านบน
- เก็บ focus ก่อนเปิดและคืน focus ตอนปิด, ล็อก scroll ของ body ระหว่างเปิด, กด Escape เพื่อปิด
- `navigator.vibrate(8 ถึง 10)` ตอนแตะ
- เคารพ `prefers-reduced-motion`
- ปุ่มลำดับใน sheet มีสามสถานะ: ของจุดนี้ (เต็มสี), ว่างและเป็นลำดับถัดไป (เส้นประสี accent), ของจุดอื่น (เส้นประ แตะเพื่อแทนที่ พร้อม toast บอกว่าแทนที่อะไร)
- ข้อความ `aria-label` บอกสถานะครบ, SVG node มี `role="button"`, `tabindex="0"` และรับ Enter/Space
- แถบเวฟเลื่อนแนวนอนแบบ snap มี mask จางที่ขอบ และเลื่อนให้ชิปที่เลือกอยู่กลาง (index.html ใช้ตาราง 4x3 แทน เพราะเห็นครบในจอเดียว)
- Shift+คลิกบนแผนที่ อ่านพิกัด x/y ไว้วางจุดเกิดตอนสร้างด่าน
