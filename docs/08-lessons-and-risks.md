## ความปลอดภัย

### Stored XSS ผ่านจุดเกิดและชื่อด่าน (แก้แล้ว 2026-10-20)

เดิม `saveSpawnPoint` และ `saveWaveData` รับสตริงอะไรก็ได้จากผู้ใช้นิรนามแล้วเขียนลงชีท แท็บตัวหนังสือและแท็บทีมแสดงชื่อสถานที่ผ่าน `shortName()` ซึ่งคืน `loc` ดิบเมื่อหาในตารางไม่เจอ แล้วต่อเข้า `innerHTML` ส่วน `setWeeklyMap` รับชื่อด่านอะไรก็ได้ และชื่อนั้นไปอยู่ในข้อความ error `map_locked` / `map_mismatch` ที่แสดงผ่าน `innerHTML` ทั้งสองทางทำให้ใครก็ฝัง HTML/JS ให้รันในเครื่องผู้เล่นคนอื่นได้

ที่แก้ไป

- server: `saveSpawnPoint` ตรวจค่าด้วย `SPAWN_RE` (ตัวอักษร ตัวเลข ช่องว่าง + `@L|C|R` + สีที่รู้จัก), `setWeeklyMap` รับเฉพาะชื่อด่านที่มีใน config (`readMapsData`) และเก็บชื่อตาม config, ลบ action `saveWaveData` ที่ไม่ได้ใช้แล้วออก
- client: `esc()` ครอบชื่อจุดและฝั่งใน `ptLabelHtml` และในแท็บทีม

ที่ยังเหลือ: ชื่อด่าน/สถานที่จาก config ในชีท และ `message` จาก server ยังถูกใส่ `innerHTML` ตรง ๆ ความเสี่ยงต่ำเพราะแก้ได้เฉพาะคนที่เข้าชีทได้หรือมีรหัสแอดมิน (`saveWeeklyMapData`) แต่แอปใหม่ควร escape ทุกที่

### รหัสแอดมิน

- เก็บเป็นข้อความธรรมดาในเซลล์ `B1` ใครที่เข้าชีทได้ก็เห็น
- client ส่งรหัสซ้ำทุกครั้งที่ Save และเก็บไว้ในตัวแปร `adminPass`
- `checkAdminPassword` ไม่จำกัดจำนวนครั้ง เดารหัสได้ไม่จำกัด

แอปใหม่ควรเก็บ hash ของรหัสใน Script Properties, ออก token อายุสั้นหลังล็อกอิน (เก็บใน `CacheService`), และจำกัดจำนวนครั้งที่ผิดต่อช่วงเวลา

### Web App เปิดให้ทุกคน

`ANYONE_ANONYMOUS` + `USER_DEPLOYING` แปลว่าใครก็เรียก API ได้ด้วยสิทธิ์เจ้าของสคริปต์ ข้อจำกัดเดียวคือสิ่งที่โค้ดตรวจ ทุก action เขียนจึงต้องตรวจ input เอง

## บั๊กที่แก้แล้ว 2026-10-20

- ตัวจับเวลาไปเวฟย่อย 4.4 ที่ไม่มีอยู่: `startSubWaveTimer` เคยใช้ `limit = nextW === 4 ? 4 : 3` (จำนวน "จุด" ของเวฟ 4) เป็นจำนวนเวฟย่อย หลัง 4.3 จึงไป 4.4 ค้าง 120 วินาที ตอนนี้ทุกเวฟมี 3 เวฟย่อย หลัง 4.3 วนไป 1.1

## บั๊กที่ยังอยู่ในโค้ด

### หน้าต่างเลือกด่านแบบ "บังคับ" ปิดได้

คอมเมนต์ของ `openMapPicker(force)` บอกว่าปิดไม่ได้จนกว่าจะเลือก แต่โค้ดแสดงปุ่ม X ทุกครั้ง และ listener ที่ `window` ปิดเมื่อแตะพื้นหลังได้ ตัวแปร `mapPickerForced` มีผลแค่ข้อความหัวหน้าต่างกับการปิดเองหลัง refresh ผลจริงไม่ร้ายแรงเพราะทุกปุ่มบันทึกเปิดหน้าต่างนี้ซ้ำ แต่โค้ดกับคอมเมนต์ไม่ตรงกัน

### ชื่อด่านที่มีสีออร่าฝังในโค้ด

`curM === 'hidden_temple'` อยู่ทั้งในหน้าแก้ไขและในตารางเวฟของแผนที่ ทั้งที่ `maps/hidden_temple.js` มี `hasAura: true` อยู่แล้ว ด่านใหม่ที่มีสีจะใช้ไม่ได้จนกว่าจะแก้โค้ด

### ข้อมูลด่านกระจายหลายที่

ชื่อและไอคอนของสถานที่อยู่ใน 5 ที่: ชีท (`B3:E14`), `mapIcons`, `NAMES_TH`, `SHORT_EN`, และ `maps/*.js` (ซึ่งมี `icon` และ `name` ของตัวเองด้วย) ค่าไม่ตรงกันอยู่แล้ว เช่นชื่อไทยของ Foundry ใน `maps/broken_castle.js` คือ "โรงหลอม" แต่ใน `NAMES_TH` คือ "โรงหล่อ" ควรรวมเป็นแหล่งเดียว (เช่นไฟล์ด่าน) แล้วให้ส่วนอื่นอ่านจากที่นั่น

## ความเสี่ยงที่ควรรู้

- กุญแจสัปดาห์เทียบด้วย `getDisplayValues()` ของ `A16` กับสตริง `d/m/yyyy` ถ้ามีใครเปลี่ยนรูปแบบเซลล์หรือ locale ของชีท ค่าที่แสดงจะไม่ตรง ระบบจะคิดว่าเป็นสัปดาห์ใหม่ทุกครั้งที่โหลด และ `getWeeklyMapData` จะล้างข้อมูลทิ้ง ตั้งเซลล์ `A16` เป็น Plain text เพื่อกันไว้
- `getWeeklyMapData` ล้างแถวข้อมูลตอนเจอสัปดาห์ใหม่โดยไม่ถือ lock ถ้ามีคนเลือกด่านในจังหวะเดียวกันพอดีอาจถูกล้างทับ
- `saveWeeklyMapData` (แอดมิน) ไม่ถือ lock และเขียนทั้งแถวทับ จุดที่ผู้เล่นบันทึกระหว่างที่แอดมินแก้อยู่จะหาย
- ตัวนับผู้เข้าชมเพิ่มทุกครั้งที่โหลดหน้า (รวม refresh) และไม่ถือ lock จึงเป็นตัวเลขคร่าว ๆ
- Tailwind CDN ไม่เหมาะกับ production (คอมไพล์ใน browser ทุกครั้ง, console มีคำเตือน)
- `render()` สร้าง HTML ใหม่ทั้งหน้าทุกครั้งที่ state เปลี่ยน และใช้ `con.innerHTML +=` ในลูป ตอนนี้ยังเร็วพอเพราะข้อมูลมี 12 เวฟย่อย ถ้าแอปใหม่มีข้อมูลมากกว่านี้มากต้องเปลี่ยนวิธี
- ไม่มี automated test มีแค่ `test.html` ที่เรียก `checkAdminPassword` ด้วยมือ
- สคริปต์ตั้ง dark mode อยู่ท้าย body หน้าอาจกระพริบสว่างก่อนเปลี่ยนเป็นมืด
- `index.html` ปิดการซูมทั้งหมด ผู้ใช้สายตาไม่ดีขยายจอไม่ได้

## ข้อเสนอสำหรับแอปใหม่ (เรียงตามความสำคัญ)

1. ตรวจ input ฝั่ง server แบบ whitelist ทุก action และ escape ฝั่ง client
2. ระบบแอดมินแบบ token + rate limit, รหัสไม่อยู่ในชีท
3. ข้อมูลอ้างอิงแหล่งเดียว และใช้ flag แทนชื่อในโค้ด
4. ทุก action เขียนผ่าน `withLock` รวมถึงการล้างข้อมูลตอนขึ้นรอบใหม่
5. เซลล์กุญแจรอบเป็น Plain text หรือเก็บใน Script Properties
6. Tailwind build เป็นไฟล์, แยก JS เป็นไฟล์ตามหน้าที่ (api, state, render, modals)
7. ใส่ `role="dialog"`, `aria-label` บนปุ่มไอคอน และจัดการ focus ตามแบบใน `maps/engine.js`
